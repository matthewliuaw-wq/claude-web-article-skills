# 校验系统详解（防概括 + 媒体完整性）

## 为什么需要校验

文章保存有两类**静默失败**，肉眼和单一脚本都查不出：

1. **媒体失败**：图片下载了却没插进正文（孤儿媒体）；md 引用了不存在的文件（坏链）
2. **内容失败**：正文在翻译/改写环节被悄悄概括或截断——文件存在、格式正常，但内容少了 30%，表面看不出来

第二类尤其危险：LLM 处理长文时有概括倾向，如果没有抓取时的基准对比，概括永远查不出。本 skill 的方案是**抓取即落基准，收尾即双校验**。

## 基准系统（抓取时落，防概括的前提）

抓取瞬间把两样东西锁定下来：

| 文件 | 内容 | 作用 |
|------|------|------|
| `_source-text.md` | 原始未加工正文（webReader 的 markdown / walker 的 `text` / snapshot 文本，原样存） | 留底对照 |
| `_source-meta.json` | 源正文长度 + 媒体数 | 供脚本对比 |

生成命令（抓到正文后立即跑）：

```bash
python3 scripts/write_source_meta.py "<输出目录>" \
  --url "文章URL" --title "标题" --method walker \
  --videos <页面 video 元素数> --imgs <正文实质图片数>
```

**没基准则 verify_completeness 只能跑翻译对齐，查不出「正文被悄悄概括」。**

## 收尾双校验

### verify_image_references.py — 媒体引用完整性（双向）

```bash
python3 scripts/verify_image_references.py "<输出目录>"
```

- **正向（查坏链）**：md 中引用的每张图片/视频是否真实存在
- **反向（查漏插）**：`images/` 里已下载的每张图片/视频，是否都被某个 md 引用
- 报告"孤儿媒体"（已下载但未被引用）= 下载了却没插进正文——必须回到生成 md 步骤按原文位置补插，重跑直到 exit 0

注意：脚本不解析 `<video>` 标签的 `poster` 属性——如果用了 poster，旁边再放一个显式 `![](images/xxx.jpg)` 避免误报孤儿。

### verify_completeness.py — 内容完整性

```bash
python3 scripts/verify_completeness.py "<输出目录>"
```

三个维度：

1. **翻译结构对齐**（无需基准，有英文原文 + 中文翻译自动跑）：对比段落/图片/列表项，**中文比英文少超阈值** = 漏段/漏图/概括（单向：中文多于英文多为翻译增值，不报）
2. **正文长度保真**（需 `_source-meta.json`）：主正文纯文本 / 抓取基准 < 70% = 被概括/截断
3. **媒体数量**（需基准）：抓取时检测的 video/img 元素数 vs 实际下载文件数，少了 = 漏检/漏下载（自动跳过 <1KB 空文件残留）

## 批量校验

对整个知识库目录批量跑双校验 + 完整度一览：

```bash
python3 scripts/check_all_articles.py <知识库根目录>
```

输出每篇文章的通过标志（双校验退出码、基准/原文/翻译/导读齐全度、媒体数）。

## 门控规则

两个校验脚本都输出 `✅`（exit 0）才算交付。任何非 0 都不许结束——要么修复问题重跑，要么明确告知用户哪里没过、为什么。

记忆口诀：**抓取即落基准，收尾即双校验。**
